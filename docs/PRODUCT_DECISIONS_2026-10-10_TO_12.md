# FunWithCam 产品决策整理（2026-10-10 至 2026-10-12）

## 1. 产品目标

FunWithCam 是运行在家庭局域网和旧 MacBook 上的本地学习助理。系统使用
go2rtc 摄像头画面与声音、本地人脸和姿态识别、MacBook 本地语音播报以及
家长 Web 页面，完成提醒、交互、学习记录和统计。

设计原则：

- 默认本地处理，不把孩子的视频、声音和人脸上传到云端；
- 系统负责提醒和记录，不替代家长判断；
- 不因为短暂离座、低头或没有写字动作就判定孩子没有学习；
- 重要状态变化必须可以在执行历史中回溯；
- 可调参数提供合理默认值，并允许家长在 Web 中修改。

## 2. 首次简报与第二次提醒

### 首次简报

首次简报不是到点直接播报。到达上学日或休息日的配置时间后，系统等待：

1. 书桌区域稳定检测到人物；
2. 多帧确认是孩子；
3. 当天尚未播放过首次简报。

识别到家长、陌生人或多人画面时不播放，也不消耗当天机会。

### 第二次提醒

当前版本在首次简报完成、孩子尚未开始学习且到达配置时间时播报。超过计划时间
30 分钟或首次简报晚于第二次提醒计划时间时，不补播旧提醒。

后续建议调整为“计划时间 + 孩子出现窗口”：到点后在一段时间内等待孩子出现再播报，
避免对空房间提醒。

## 3. 学习开始与基准采集

孩子可通过 Web 或语音开始学习。开始前检查摄像头、书桌区域、单人画面、孩子身份和
光线，通过后建立学习记录。

动作基准分为正常坐姿、正常写字、正常阅读和正常光线。身份确认与动作采集必须分阶段：

1. 孩子先短暂正对摄像头完成一次身份确认；
2. 身份确认后开始计算动作采集时间；
3. 写字和阅读时不要求持续检测到人脸；
4. 多人画面或确认后明确识别到家长仍然拦截；
5. 家长在 Web 中查看原图和标注图后确认。

原因是写字和阅读天然包含低头、侧脸和遮挡，如果整段采集都要求连续看到正脸，会导致
真实动作无法录入。

## 4. 受控语义匹配

语音指令不做无边界模糊匹配，而采用可配置的受控语义匹配：

1. **明确短语匹配**：例如“开始学习”“开始写作业”；
2. **关键词组合匹配**：例如一组“开始/准备/要”和一组“学习/作业/记录”；
3. **状态约束**：同一句“开始”在等待学习、打卡准备和暂停状态下含义不同；
4. **二次确认**：组合匹配或高影响操作先询问，再执行；
5. **冲突拒绝**：同时命中多个意图时不猜测。

家长可以配置：

- 明确说法；
- 关键词组合；
- 不确认、仅组合匹配确认、始终确认；
- 确认话术；
- 可以接受的确认和取消回复；
- 是否启用。

查询作业和课程可以直接回答；结束学习始终进入完成情况检查；开始视频打卡必须经过准备
和明确的“开始打卡”信号。

## 5. 确认与重复询问

系统提问必须同时告诉孩子可以怎样回答。例如：

> 你刚才离开了一会儿。如果要继续，请说“继续学习”；如果已经完成，请说“结束学习”。

默认重问策略：

- 第一次询问后等待 20 秒；
- 第二次后等待 60 秒；
- 最多询问 3 次；
- 仍无有效回答时停止询问，保持原状态，不自动判定完成。

家长可以配置等待时间和最大次数。重复询问有上限，不能无限播报。

## 6. 离座和结束判断

摄像头不能可靠判断作业是否完成，因此长时间离座不能直接标记为“已完成”。

目标状态流：

```text
正在学习
→ 离座宽限
→ 超过阈值自动暂停
→ 孩子回来并确认身份
→ 询问“继续学习”或“结束学习”
→ 无回答则保持暂停
→ 长时间未返回则标记异常中断
```

默认建议：

- 连续离座 2 分钟自动暂停；
- 长时间未返回 60 分钟标记异常中断；
- 回来后最多询问 3 次。

这些阈值已经进入 Web 配置。持续视觉检测尚需接入学习中的后台监控后才会自动触发。

## 7. 结束学习后的任务检查

“结束学习”不是立即关闭记录，而是：

```text
提出结束
→ 确认结束意图
→ 检查当天未完成任务
→ 处理视频打卡
→ 汇总结果
→ 最终结束
```

结束检查结合当天日程，只询问实际存在且尚未完成的任务。

完成证据区分：

- 孩子语音确认；
- 已保存视频；
- 家长确认；
- 稍后完成；
- 跳过；
- 未回答。

不能把孩子口头确认和已有打卡视频混为同一种证据。

## 8. 任务和打卡类型

初始内置：

- 学校作业：语音确认；
- 英语单词打卡：视频；
- 英语读书打卡：视频；
- 古诗词背诵：视频。

家长可以增加课外阅读、口算、乐器、体育等自定义类型，并配置：

- 类型名称和类别；
- 完成证据；
- 是否进入结束检查；
- 结束检查话术；
- 视频最大时长；
- 是否允许日程选择。

家长在 Web 中手动把任务标记为完成时，系统记录为“家长确认”。配置为
“家长确认”的任务不能由孩子仅凭口头回复标记完成。

## 9. 视频打卡交互

标准流程：

1. 孩子说“英语读书打卡”等明确口令；
2. 系统匹配当天对应任务；
3. 系统提醒准备材料并说明“开始打卡/取消打卡”；
4. 孩子说“开始打卡”，系统启动 FFmpeg 录制 go2rtc 的视频和音频；
5. 录制期间只接受“打卡结束/取消打卡”等明确控制指令；
6. 结束后保存本地 MP4，并将任务完成证据标记为视频；
7. 执行历史记录准备、开始、结束和失败原因。

视频保存在本机数据库同级的 `checkins/<日期>/` 目录。后续需要继续补充缩略图、Web
播放、重新录制和保留期限。达到任务类型配置的最长录制时长时，当前版本会自动停止、
保存视频并记录完成证据。

## 10. 已确认但尚未完成的能力

- 学习过程中的持续视觉检测；
- 离座自动暂停和回来后自动发起询问；
- 坐姿、头部过低、光线和频繁离座的主动提醒引擎；
- 打卡视频缩略图、Web 播放和重新录制；
- 第二次提醒改为“到点后等待孩子出现”；
- 语音监听线程真实健康状态展示与自动重启。
